[재고 관리]의 [부품 요청 관리]에 종류 [반환]으로 뜨게 … 관리자가 [반환] 버튼을 누르고 [사용] 요청이 왔을 때 [승인요청]하는 팝업이 뜨듯이 한 번 더 확인하고 [반환 완료] … (반환에는 승인 절차가 필요 없어.)
포털 알림은 [반환 요청]은 [확인대기]를 [반환 완료]시에는 [결재 결과]를 따르도록 … 알림설정의 각각의 설명 내용에 [반환]에 대한 내용을 추가」

일이 지나가는 길

A/S[반환 요청] 팝업
→
재고 관리[부품 요청 관리] · 종류 반환
→
재고 관리[반환] → 확인 팝업 → [반환 완료]

그리고 양 끝에서 포털의 종이 울립니다 — 올릴 때 「확인 대기」, 끝났을 때 「결재 결과」. 승인 절차는 중간에 없습니다.

이미 있어서 안 만들어도 되는 것

「반환」은 재고 관리에 이미 90%가 만들어져 있었습니다
  • 종류 목록에 반환 값이 이미 있습니다 — 화면에 뜨는 라벨 「반환」도 이미 있습니다
  • 되돌릴 원래 거래를 가리키는 칸이 있습니다
  • 「이미 반환한 만큼 빼고 남은 것만」 검증이 이미 돌아갑니다
  • 후보를 뽑는 함수가 나간 양 · 이미 반환한 양 · 남은 양을 이미 계산합니다
  • 알림 색은 자동으로 정해집니다 — 고를 것이 없습니다
  • 「확인 대기」 알림은 거저 따라옵니다 — 건수를 세는 질의가 종류를 안 가립니다

그래서 마이그레이션이 0건입니다. 표에 칸을 하나도 안 더합니다.

그런데 막혀 있던 것 둘

ㄱ) A/S 가 「얼마나 돌려줄 수 있는지」를 알 길이 없습니다

지금 A/S 가 재고 관리에서 받아 오는 값에는 나간 수량만 있고 이미 반환한 수량이 없습니다. 그대로 두면 같은 부품을 두 번 반환해 넘깁니다.

→ 조각 ①에서 반환 후보를 주는 통로를 새로 냅니다. 남은 수량은 재고 관리가 계산해 줍니다(그 계산은 이미 있습니다).

ㄴ) 신청을 받는 통로가 「종류는 사용 고정」으로 못 박혀 있습니다

바깥에서 들어오는 신청은 종류를 고를 수 없게 코드로 막혀 있습니다.

→ 조각 ②에서 같은 통로에 반환만 더 엽니다. 새 통로를 내면 인증과 검사가 두 벌이 됩니다.

조용히 깨질 뻔한 것 — 「승인 절차 없음」이 저절로 안 됩니다

결재 범위를 고르는 함수가 종류를 안 보고, 갈래가 비면 「부품 불출」 범위로 보냅니다. 재고 관리 관리자가 그 범위에 결재를 이미 켜 뒀다면 — 반환 신청도 조용히 결재로 끌려갑니다.

→ 종류가 반환이면 결재를 안 탄다를 조각 ②에서 값으로 못 박습니다.

🔵 시험으로도 누릅니다 — 결재가 켜져 있어도 반환은 결재 대상이 아니다. 그 시험이 없으면 이 결함은 운영에서 관리자가 결재를 켜는 날 처음 드러납니다.

조각 ①이 찾아낸 것 둘 — 둘 다 조각 ②에서 함께 다룹니다

ㄱ) 담당자가 직접 넣는 반환 화면이 최댓값을 「나간 − 이미 반환」으로 셉니다 — 대기 중인 신청을 모릅니다. 조각 ②가 신청을 세우기 시작하면 같은 부품에 두 화면이 다른 최댓값을 말하고, 담당자가 전부 반환해 버리면 나중에 그 신청의 [반환 완료]가 넘쳐서 거절됩니다.

ㄴ) 「요청으로 세우기」가 담당자 직접 입력까지 바꿀 뻔했습니다. 가르는 함수를 재고 관리 자체 화면도 함께 씁니다 — 종류만 보고 넣으면 담당자가 직접 넣던 반환까지 「요청」으로 서게 됩니다. 그건 요청받은 일이 아닙니다. → 「바깥에서 온 것인가」도 함께 봐야 합니다.

조각 ②가 값으로 끝낸 것 셋
  • 걱정이 개발 DB 에서 이미 참이었습니다 — 부품 불출 결재가 3단계로 켜져 있었습니다. 갈래를 비워 두기만 했으면 반환이 그대로 끌려갔습니다. → 결재가 켜져 있어도 안 탄다를 시험으로 눌렀습니다.
  • 위 ㄴ)은 고칠 필요가 없었습니다 — 바깥 통로는 그 판정 함수를 아예 안 거칩니다. 담당자가 직접 넣는 반환은 한 글자도 안 바뀌었습니다.
  • 실제로 두드려 봤습니다 — 남은 9 → 2개 신청 → 대기 2 · 남은 7 → 같은 열쇠로 또 보내면 멱등 → 8개는 거절(「7개까지 돌려줄 수 있습니다」). 쪼개기도 가장 먼저 나간 두 줄에 1개씩 담겼습니다. 세운 신청과 감사 로그는 치웠고 수가 원래대로 돌아온 것까지 확인했습니다.
조각 ②가 찾아낸 것 — 조각 ④가 함께 합니다

[부품 요청 관리]에 선 반환 신청은 「무엇을 돌려받는지」가 안 보입니다. 요약이 반환 · 2026-11-26 뿐이고 부품 줄도 인수번호도 없습니다 — 부품 줄을 뽑는 함수가 반환을 빈 배열로 돌려주기 때문입니다(반환 줄은 부품이 아니라 원장 줄을 가리킵니다).

🔵 「한 번 더 내용을 확인하고 [반환 완료]」를 하려면 그 내용이 보여야 합니다. → 조각 ④ 범위에 넣었습니다.

🔵 좋은 쪽으로 하나 틀렸습니다 — 알림 설명 문구가 재고관리에 있습니다. 포털은 각 시스템에서 그 글을 받아다 보여 줄 뿐이라, 포털 저장소는 한 글자도 안 고칩니다.
