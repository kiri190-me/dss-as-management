PO 의 [폴더 열기]를 실제로 눌러 보지 못한 까닭

2026-09-28 · 조각 PO 3g(폴더 열기 이식) 뒤에 실측한 내용입니다. 결론부터 쓰면 — PO 쪽 설정 파일에 두 줄이 없어서입니다. 코드 문제가 아니고, 도우미 설치 문제도 아닙니다.

1[폴더 열기]가 실제로 하는 일

브라우저는 웹 페이지에서 Windows 탐색기를 직접 열 수 없습니다. 그래서 이 단추는 세 군데를 거칩니다.

1
서버가 공유폴더에서 그 견적서의 폴더를 찾는다 GET /api/quotes/{id}/archive-folder 가 공유폴더 뿌리에서 연도 폴더 / 견적서 폴더 를 찾아, 뿌리 기준 상대 경로만 돌려줍니다. 서버 안의 실제 경로는 응답에 싣지 않습니다.
↓
2
화면이 도우미 주소를 만든다 dss-folder://open/?p=… — 상대 경로를 base64url 로 싸서 붙입니다.
↓
3
그 PC 에 설치된 도우미가 탐색기를 연다 PC 마다 한 번 설치하는 PowerShell 스크립트(open-dss-folder.ps1)가 그 주소를 받아, 자기 안에 박힌 공유폴더 뿌리에 상대 경로를 붙여 탐색기로 엽니다.
그래서 눌러 보려면 조건이 셋입니다. ① 서버에 공유폴더 설정이 있을 것 · ② 그 견적서의 폴더가 실제로 만들어져 있을 것 · ③ 그 PC 에 도우미가 설치돼 있을 것.

2세 조건을 실제로 재 봤습니다

조건 무엇 A/S PO 실측
①
서버 설정		 QUOTE_ARCHIVE_DIR
서버가 보는 경로		 있음 없음 A/S 쪽 값은 실제로 닿습니다(폴더가 열립니다).
QUOTE_ARCHIVE_UNC_ROOT
사람이 보는 주소		 있음 없음 [위치 복사]에 쓰는 값입니다. 없어도 폴더 열기 자체는 돌지만, PO 에는 둘 다 없습니다.
②
폴더		 그 견적서의 폴더가 공유폴더에 있는가 있음 (4건) 뿌리 아래 연도 폴더 1개, 그 안에 견적서 폴더 4개, 각 폴더에 .xlsx 1장. A/S 와 PO 는 같은 DB 를 보므로 PO 에서도 그 4건이 보입니다.
③
도우미		 이 PC 에 dss-folder 가 설치돼 있는가 설치됨 %LOCALAPPDATA%\DSS\open-dss-folder.ps1 — 2026-09-16 · 175줄, HKCU\Software\Classes\dss-folder 등록됨.

막고 있는 것은 ① 하나뿐입니다

②(폴더)와 ③(도우미)은 이미 갖춰져 있습니다. PO 의 .env.local 에 설정 두 줄이 없어서 1단계에서 끝나는 것입니다.

3그래서 지금 화면에 뜨는 것

서버는 공유폴더 뿌리 설정이 없으면 { status: "disabled" } 를 돌려줍니다. 화면은 그것을 이렇게 보여 줍니다.

PO · /quotes/{id} — 견적서 편집 화면
폴더 열기 공유폴더 저장이 꺼져 있습니다

이것은 고장이 아니라 설계된 응답입니다. 설정을 켜지 않은 환경(예: 공유폴더에 닿지 않는 서버)에서 단추가 오류를 뱉지 않고 꺼져 있다고 알리도록 되어 있고, A/S 도 같은 방식입니다.

설정을 켜면 이렇게 갈립니다

서버 응답화면
found 도우미 주소를 열고, 탐색기가 뜹니다. 함께 [위치 복사]도 쓸 수 있습니다.
not-found 「아직 공유폴더에 이 견적서의 폴더가 없습니다 — [견적서 받기]를 먼저 눌러 주세요」
disabled 「공유폴더 저장이 꺼져 있습니다」 ← 지금 이것
failed 까닭을 그대로 보여 줍니다(폴더 이름에 도우미가 열 수 없는 글자가 있는 경우 등).

4제가 켜지 않은 까닭

설정 파일은 제가 손대지 않습니다

.env.local 은 프로젝트 규칙상 내용을 출력하지도, 고치지도 않는 파일입니다. 이 문서에도 실제 경로 값은 한 글자도 적지 않았습니다 — 「있다 · 없다 · 닿는다」만 적었습니다. 또 그 두 줄은 사내 NAS 주소라서, 값을 넣는 일은 사용자가 직접 하는 편이 맞습니다.

도우미가 없는 화면은 이 PC 에서 재현할 수 없습니다

「이 PC 에 폴더 열기 도우미가 없는 것 같습니다 — [설치 명령 복사]를 …」 화면은 도우미가 설치돼 있지 않은 PC 에서만 뜹니다. 이 PC 에는 2026-09-16 에 이미 설치돼 있어서, 그 화면을 보려면 레지스트리 등록(HKCU\Software\Classes\dss-folder)을 지워야 합니다. 그것은 A/S 쪽 폴더 열기까지 함께 망가뜨리므로 하지 않았습니다.

5실제로 눌러 보시려면

아래 두 단계면 됩니다. 코드는 건드리지 않습니다.

1
A/S 의 .env.local 에서 두 줄을 그대로 복사해 PO 의 .env.local 에 붙여넣기 RF_Service_System/.env.local → dss-po/.env.local. 옮길 줄은 QUOTE_ARCHIVE_DIR=… 와 QUOTE_ARCHIVE_UNC_ROOT=… 둘입니다.
⚠️ 같은 이름이 이미 아래쪽에 또 있으면 나중 줄이 이깁니다 — 중복이 없는지 확인해 주세요.
↓
2
PO 개발 서버를 껐다 켜기 .env.local 은 서버가 뜰 때 한 번만 읽습니다. 켠 채로 고치면 안 먹습니다.
↓
3
폴더가 이미 있는 견적서를 열고 [폴더 열기] 아무 견적서나 누르면 not-found 가 뜹니다 — 폴더는 [견적서 받기]가 만들기 때문입니다. 공유폴더에 폴더가 있는 것은 지금 4건(견적서 번호 2026-077 · 078 · 079 및 1건)입니다. 그 4건 중 하나를 열면 탐색기가 떠야 정상입니다.

되돌리려면

붙여넣은 두 줄을 지우고 서버를 다시 켜면 원래대로 「꺼져 있습니다」로 돌아갑니다. DB 나 공유폴더에는 아무것도 쓰이지 않습니다 — 이 통로는 읽기만 합니다(폴더를 만들지도, 감사 기록을 남기지도 않습니다).

6그럼 무엇은 확인된 것인가

실기로 못 본 것은 탐색기가 실제로 뜨는 마지막 한 걸음뿐입니다. 그 앞은 A/S 에서 이미 쓰이고 있는 코드를 글자 그대로 옮긴 것이고, 시험으로 확인했습니다.

무엇확인 방법내용
주소 만들기 · 되읽기 단위 시험 base64url 싸기, 절대 경로 · .. · 금지 글자 · 끝의 점/공백 거절
서버 통로의 순서 소스 시험 세션 → 권한 → id → 견적서 → 뿌리 → 찾기 순서와, 결재 표를 읽지 않는다는 것
네 갈래 화면 컴포넌트 시험 found · not-found · disabled · failed 각각의 문구와 단추
도우미 스크립트 규칙 단위 시험 화면 쪽 규칙과 PowerShell 쪽 규칙이 같은지 맞춰 봅니다
탐색기가 실제로 뜨는 것 못 함 위 5절을 하면 볼 수 있습니다
A/S 에서는 이미 돌고 있는 기능입니다. 2026-09-16 에 A/S 에 들어갔고, 이 PC 의 도우미도 그때 설치된 것입니다. PO 로 옮긴 코드는 문지기 한 자리(세션 확인 방식)만 다르고 나머지는 같습니다.
2026-09-28 작성 · 측정값은 이 PC 에서 직접 잰 것입니다. 실제 경로 · 공유폴더 주소 · 고객명은 규칙에 따라 이 문서에 적지 않았습니다.
