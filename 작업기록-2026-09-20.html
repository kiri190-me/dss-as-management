1. 개선요청 사이트 — 두 가지를 붙였습니다

끌어다 놓기

스크린샷을 글 위로 끌어다 놓아 올릴 수 있게 됐습니다. 새 글 쓰는 칸과 목록의 글 줄, 두 자리 모두입니다. A/S 시스템에 있던 것을 옮겨 왔습니다.

처음에는 사진 띠만 과녁으로 삼았는데, 사진이 없는 줄에서는 그것이 단추 한 줄 높이(26px)뿐이라 줄의 80%가 과녁 밖이었습니다. 순수 함수 시험 21개가 전부 통과하는데도 화면에서는 아무 일도 일어나지 않았습니다. 지금은 줄 전체가 과녁이고, 같은 실수를 막는 배선 시험을 함께 넣었습니다.

파일 찾기가 사진 폴더에서 열립니다

「가끔 파일 찾기가 늦게 뜬다」고 알려주신 건, 윈도가 마지막에 쓴 폴더를 훑기 때문이었습니다. 그것이 OneDrive 폴더면 클라우드 목록을 받아오느라 몇 초 걸립니다. 이제 사진 폴더에서 시작합니다 — 이 PC 의 사진 폴더는 로컬이라 기다릴 일이 없습니다.

🔴 진짜 원인은 따로 있었습니다 — 버튼이 전부 죽어 있었습니다

「끌어다 놓기가 안 된다」에 이어 「[스크린샷 추가] 버튼도 안 눌린다」고 알려주신 것이 결정적이었습니다. 그건 우리가 만들지 않은 버튼이었으니까요.

원인은 이 PC 의 Wi-Fi 주소가 192.168.35.215 인데 설정에는 192.168.0.* 와 192.168.1.* 만 적혀 있던 것이었습니다. 그러면 Next 가 개발용 자산을 막고, 화면은 멀쩡히 뜨는데 React 가 붙지 않아 모든 버튼이 죽습니다. 대역 전체(192.168.*.*)로 넓혀 해결했습니다.

2. 연락서 판독기 — 방향을 정하고 첫 도구를 만들었습니다

먼저 「보여줘도 되는가」를 따졌습니다

이 계정은 Claude Team 이라 상업 약관이 적용됩니다. 대화 내용이 모델 학습에는 쓰이지 않습니다. 다만 「안 보낸다」는 아닙니다 — 30일간 서버에 남고, 이 PC 에도 평문으로 30일 쌓입니다. 그래서 판본별 대표 샘플 몇 장만 보기로 정하셨습니다.

450장을 다 보는 대신 판독기를 만듭니다

연락서가 450장이라 제가 눈으로 읽는 방식은 검증이 불가능합니다. 한 장을 잘못 옮겨도 아무도 모르고, 다음 달 새 연락서가 오면 처음부터 다시입니다. 판독기는 시험으로 검증되고 NAS 에서 혼자 돕니다.

고객 내용이 자동으로 걸러지는 규칙 하나

판본 조사 도구를 만들었습니다. 글자를 그대로 적는 기준은 하나입니다 — 서로 다른 파일 여러 장에 똑같이 나온 것만. 양식 라벨은 모든 파일에 공통이라 남고, 고객 고유값(모델·S/N·증상)은 그 파일에만 나오니 자동으로 가려집니다. 450장 중 449장은 내용이 제게 오지 않습니다.

이 PC 의 3장으로 시험해 판본 2가지를 갈랐습니다(매처 15시트 · 제너레이터 26시트). 같은 라벨이 판본마다 21행 아래로는 거의 전부 어긋난다는 것도 실측으로 확인했습니다 — 판독기가 칸 주소가 아니라 라벨 글자로 찾아야 하는 근거입니다.

3. PO/내자 분리 — 가장 큰 일의 첫 조각

메뉴 그룹 「PO / 내자」(내자 정리 · 견적서 · 작업 비용, 약 73,000줄)를 별도 사이트로 떼어냅니다. 조사 넷을 돌려 설계서를 쓰고, 첫 조각을 끝냈습니다.

DB 를 함께 보는 것은 이번만입니다. 내자는 화면 자체가 표 다섯 개를 조인한 결과라 나눌 수 없어서 그렇습니다. 앞으로 생길 시스템이 정보 일부를 주고받을 때는 API 를 씁니다.

DB 를 계속 합치면 마이그레이션과 배포가 묶입니다 — 칸 하나 고치자고 다섯 번 배포하게 됩니다. 검색·정렬이 필요하면 필요한 조각만 자기 DB 에 사본으로 두는 가운데 길이 있습니다.

끝낸 조각 — 스키마 이사

4. 오늘 잡은 함정

무엇왜 위험했나
개발 주소 대역 화면은 멀쩡한데 버튼만 전부 죽어, 원인을 코드에서 찾게 만듭니다
파일 찾기의 id 옵션 주면 브라우저가 마지막 폴더를 기억해 사진 폴더 설정을 무시합니다. 문서에는 어느 쪽이 이기는지 안 나와 있어 규격 원문과 브라우저 소스를 직접 읽어 갈랐습니다. 시험으로는 절대 안 잡히는 종류입니다
스키마를 글자로 읽던 자리 파일을 import 가 아니라 내용으로 읽는 시험이 하나 있었습니다. import 만 세면 안 보입니다
두 번째 drizzle 설정 한쪽만 고치면, 누가 그걸로 마이그레이션을 만드는 날 「표를 전부 지우는」 SQL 이 나올 수 있었습니다
판본 지문 규칙 제 첫 지시서대로였다면 450장에서 판본이 450가지로 갈렸을 것입니다
비밀값 평문 파일 포털 접속 비밀값이 든 백업 파일이 디스크에 남아 있었습니다. 지웠습니다

6. 기억해 두실 것

🔴 클론할 때 --recurse-submodules

이제 A/S 저장소에 서브모듈이 둘입니다 — vendor/dss-ui(메뉴바)와 vendor/dss-core(DB 설계도). 빠뜨리면 빈 폴더가 되어 빌드가 크게 실패합니다. 조용히 옛 코드가 쓰이지는 않으니 알아채기는 쉽습니다.

포털에 localhost 가 등록됐습니다

개선요청 사이트에 사내망 주소와 localhost 둘 다 등록했습니다. 보안 컨텍스트가 필요한 기능(파일 찾기 시작 폴더 · 클립보드 · 카메라 같은 것)은 HTTPS 나 localhost 에서만 동작하므로, 이게 없으면 개발 PC 에서 영영 시험할 수 없습니다.

다만 .env.local 의 SSO_REDIRECT_URI 를 잠시 바꿔야 하는 번거로움이 남습니다. auto 가 「지금 접속한 주소」를 따라가게 만들면 그 왔다 갔다 가 없어집니다 — 나중 과제입니다.
