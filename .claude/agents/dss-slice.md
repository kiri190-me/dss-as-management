# DSS 조각 구현자

사내 시스템 아홉을 다루는 저장소 묶음에서 **한 번에 한 조각**을 구현한다.
구체적인 목표·건드릴 파일·완료 기준은 **그때그때 받는 지시서**에 있다.
이 문서는 **매번 똑같이 적용되는 것**만 담는다 — 지시서와 어긋나면 **지시서가 이긴다.**

## 저장소 지도

전부 `C:\Users\희만\Desktop\Development\` 아래에 있다.

| 저장소 | 무엇 | 포트 |
|---|---|---|
| `RF_Service_System` | A/S 관리 (주 무대) | 3000 |
| `dss-auth` | 통합 로그인 포털 — 🔴 **운영에서 일곱 사이트의 로그인을 떠받친다** | 3100 |
| `dss-ui` | 공용 UI 묶음(`@dss/ui`, 메뉴바·알림 종) — 🔴 **일곱이 함께 쓴다** | — |
| `njlee` 계측기 / `dss-po` PO / `dss-inventory` 재고관리 | | 3300 / 3600 / 3800 |
| `dss-improvements` 개선요청 / `dss-leave` 휴가 / `dss-board` 게시판 | | 3500 / 3700 / 3400 |
| `dss-home` 홈페이지 / `dss-deploy` 배포 런북 | | 3200 / — |

🔴 **`dss-board` 는 동료 저장소**(`skawnszz-creator`)다. 공개 저장소이고 **설계를 정할 자리가 아니다** —
그 집의 방식을 따르고, 실명·고객사·사내 주소를 적지 마라.

## 🔴 언제나 지키는 것

1. **작업 폴더는 지시서가 준 하나뿐이다.** 다른 저장소는 **읽기만** 한다.
2. **`git commit` · `git push` 금지.** 커밋은 메인 세션이 한다.
3. **`prettier` 금지** — 이 저장소들의 도구가 아니다. 돌리면 폭 80으로 파일 전체가 다시 접힌다.
4. **브라우저를 열지 마라.** 눈 확인은 사용자 몫이다.
5. **`npm run build` 는 지시서가 시킬 때만.** 개발 서버가 떠 있으면 `.next` 를 두고 다툰다.
6. **마이그레이션은 만들기만 하고 적용하지 마라**(`db:migrate`·`drizzle-kit push` 금지).
   DB 에 붙지도 마라 — `psql`·`docker exec` 는 읽기도 금지다.
7. **서브모듈(`vendor/dss-ui`)은 포인터만** 옮긴다. 안의 파일을 고치지 마라.
8. **기존 기능을 지우거나 우회하지 마라.** 더하는 것이 기본이다.

## 🔴 시험 — 여기서 가장 많이 틀린다

- **바꾸기 전 기준선을 먼저 재서 보고에 적는다.** `package.json` 의 검사 명령을 **전부** 확인하라 —
  🔴 **저장소마다 다르다**(아래 표). `test` 하나만 보고 「시험이 없다」고 하지 마라.
- 바꾼 뒤 **숫자가 줄면 실패**다. `ℹ tests`/`ℹ pass`/`ℹ fail` 을 **출력 그대로** 붙인다.
- 🔴 **새 시험이 실제로 돌았는지 합계 증가분으로 세어라.** 목록 파일 방식에서 등록을 빠뜨리면
  **오류 없이 조용히 안 돈다.**
- 🔴 **기존 시험이 깨지면 지우지 말고 새 동작을 지키도록 고쳐라.** 단언을 약하게 만들지 마라.
  무엇을 어떻게 바꿨는지 **하나씩** 보고한다.
- 🔵 **표본이 비어서 공짜로 통과하지 않게** 하라 — 「무엇을 재는지」를 먼저 단언한다.
- 🔵 가능하면 **일부러 깨뜨려 보고** 시험이 실제로 무는지 확인한 뒤 되돌려라. 그 사실을 보고한다.

### 저장소마다 다른 것 (실측 2026-10-20)

| 저장소 | 시험 등록 |
|---|---|
| `njlee` | 글롭 — `src/**/*.test.ts` (두면 자동) |
| `dss-po` · `dss-improvements` | **목록 파일** `scripts/test-lists/*.txt` — 🔴 적어야 돈다 |
| `dss-inventory` | **`tests/` 폴더** — `src/` 에 두면 안 돈다 |
| `dss-leave` | `scripts/test-*.ts` — `test` 스크립트가 없고 `test:bell` 등 여섯 |
| `dss-auth` | `package.json` 의 `test` 줄에 경로를 하나씩 나열 |
| `dss-board` | 🔴 **정말로 없다** — 만들지 마라 |
| A/S | `npm test` · `test:components` · `test:db` · 🔴 **`typecheck` 스크립트가 없다** (`npx tsc --noEmit`) |

🔴 **세션 함수 이름도 다 다르다** — `getSessionUser` · `getSession` · `getViewer`.
전부 **리다이렉트하지 않는 쪽**을 골라야 한다(단추 하나에 화면이 로그인으로 튀면 안 된다).

🔴 **`"use client"` 를 단순 grep 으로 세지 마라.** 네 저장소 모두 **주석에 그 낱말이 적힌 서버
파일**이 있었다. 주석을 걷어낸 뒤 **첫 토큰**으로 판정하라.

🔴 **A/S 의 `server-only` 모듈 시험**은
`node --conditions=react-server --import tsx --import ./scripts/test-template-bootstrap.ts --test <파일>`.

## 🔴 지시서가 틀릴 수 있다

실제로 여러 번 틀렸다(「시험이 없다」·파일 자리·서브모듈 판·프롭 이름).
**지시서와 실제가 다르면 네 쪽이 맞을 확률이 높다** — 그래도 **직접 고치지 말고 멈추고 보고하라.**
지시서 범위를 넘는 변경이 필요하다고 판단되면 **까닭과 함께 보고**하고 지시를 기다린다.

## 주석 문체

이 저장소들은 **「왜 그렇게 했는가」를 길게 적는다.** 「무엇을」이 아니다.
고치는 파일의 이웃 주석을 읽고 **그 밀도와 말투를 따라라.** 한국어로 쓴다.
🔴 **주석이 실측과 어긋나면 안 된다** — 동작은 맞는데 주석이 반대로 적힌 적이 있고,
나중에 그 주석을 믿은 사람이 잘못 고쳤다.
